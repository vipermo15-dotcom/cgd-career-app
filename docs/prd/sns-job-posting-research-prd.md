# PRD: SNS 채용공고 리서치 (재학생 취업시스템)

## 1. 개요

### 1.1 목적
재학생(교육생)이 목표 직무에 맞는 채용공고를 찾을 때, 기업 공식 채용페이지·채용 플랫폼뿐 아니라 **SNS(인스타그램, 스레드, 메타/페이스북, X)에 게시되는 채용공고**까지 수집하여 Matching·Application 단계에 활용할 수 있는 정규화된 Job Record로 만든다.

### 1.2 배경
- 디자인/크리에이티브 직군, 스타트업, 소규모 스튜디오는 공식 채용 플랫폼보다 SNS(특히 인스타그램 피드/스토리, 스레드, 페이스북 페이지)에 먼저 채용 공고를 올리는 경우가 많다.
- 기존 `career-job-research` 스킬은 기업 공식 채용 페이지·주요 채용 플랫폼을 1순위 소스로 다루며, SNS는 아직 파이프라인에 포함되어 있지 않다.
- 크롤러 커넥터(Firecrawl)를 활용해 SNS 공개 게시물을 수집·정규화하는 별도 단계가 필요하다.

### 1.3 범위
- 수집 대상: Instagram(공개 게시물/해시태그), Threads, Meta(페이스북 페이지), X(트위터)
- 비대상(이번 PRD 범위 제외): 비공개 계정, 로그인 필요 콘텐츠, DM 기반 채용 제안, 유료 API 연동(공식 Graph API 등)은 후속 과제로 분리

## 2. 목표 및 성공 지표

| 목표 | 지표 |
|---|---|
| SNS 채용공고 커버리지 확보 | 목표 직무군별 SNS 발견 공고 수 / 전체 발견 공고 수 |
| 중복/노이즈 최소화 | 정규화 후 중복 제거율, False Positive(채용공고 아님) 비율 |
| 신선도 신뢰성 | 마감 지난 공고를 "지원 가능"으로 오표시한 건수 = 0 |
| 재현 가능한 파이프라인 | 동일 조건 재실행 시 결과 일관성 |

## 3. 필요 스킬 선정 (진행 전 선행 작업)

SNS 채용공고 리서치는 신규 스킬을 새로 만들기보다, 기존 `career-job-research` 스킬의 파이프라인을 SNS 소스로 확장하는 방식으로 진행한다.

- **anthropic-skills:career-job-research** (기준 스킬) — 검색 → 후보군 → 중복제거 → 신선도 검증 → 출처/기업 검증 → 요건 추출 → 정규화 → 신뢰도 → 매칭 입력 파이프라인을 그대로 채택하고, "검색" 단계에만 SNS 소스를 추가한다.
- **Firecrawl 커넥터** (`mcp__Firecrawl__firecrawl_search`, 필요 시 developer/research 계열은 미사용) — SNS 공개 페이지 크롤링·검색에 사용. 로그인 세션이 필요한 비공개 영역은 다루지 않는다.
- 매칭·포트폴리오·기업 리서치 등 후속 스킬(`career-matching`, `career-company` 등)은 이 PRD의 산출물(정규화된 Job Record)을 입력으로만 사용하며, 이번 범위에는 포함하지 않는다.

> 원칙: 새 스킬을 만들기 전에 기존 스킬로 커버되는지 먼저 확인하고, 커버되지 않는 차이(SNS 소스 특유의 검증 규칙)만 확장한다.

## 4. 단계별 진행 계획

### Phase 0 — 스킬/소스 확정 (선행)
- 위 3장의 스킬 조합 확정
- 플랫폼별 접근 가능 범위 확인: 각 플랫폼의 공개 검색/해시태그/공개 페이지 접근 가능 여부를 Firecrawl로 사전 테스트
- 각 플랫폼 ToS(이용약관) 상 크롤링 허용 범위 확인 → 허용되지 않는 방식(로그인 우회, 비공개 콘텐츠 접근, 과도한 요청)은 배제

### Phase 1 — 단일 플랫폼 파일럿 (Instagram) ✅ 완료
- 목표 직무 키워드 + 채용 관련 해시태그(예: #채용, #디자이너채용)로 Firecrawl 검색
- 검색 결과 → 후보 Job Record 초안 생성 (Job Summary/Source/Deadline 후보만)
- 수동 검증으로 False Positive율 측정, 임계치 설정
- **결과**: [Phase 1 파일럿 리포트](./phase1-instagram-pilot-report.md) 참고. Instagram/Facebook/Threads/X 4개 플랫폼에 동일 쿼리로 비교 실행 완료.
- **주요 발견**:
  1. 이 환경의 Firecrawl 커넥터는 `firecrawl_search`(검색 스니펫)만 제공하며 전체 페이지 scrape 도구는 없음 → 마감일/전체 요건 등은 스니펫만으로 채울 수 없어 `UNKNOWN`/`AMBIGUOUS`로 남기는 것을 기본 동작으로 확정 (5.1절 반영)
  2. X(트위터)는 "채용공고에 대한 개인 코멘트"가 섞여 False Positive율이 가장 높음(10건 중 6건) → 1인칭 채용 공지 문구 기반 1차 필터 필요
  3. Threads/Instagram의 채용 큐레이션 계정은 게시물 1건에 여러 기업 공고가 요약되어 있음 → 게시물 1건을 Job Record 여러 건으로 분리하는 규칙 필요
  4. 소스가 기업 공식 계정 직접 게시인지, 큐레이션 계정의 재게시인지에 따라 Research Confidence를 차등 적용해야 함

### Phase 2 — 파이프라인 정식 적용 (Instagram) ✅ 완료
- `career-job-research` 파이프라인 전 단계 적용: 중복제거 → 신선도 검증 → 출처 검증(작성 계정이 실제 기업/채용 담당 계정인지) → 요건 추출(MUST/PREFERRED/AMBIGUOUS) → 정규화 → Research Confidence 산출
- SNS 특유 리스크 반영: 게시일 ≠ 마감일인 경우가 많으므로 "마감일 명시 없음"은 상태를 UNKNOWN으로 두고 임의로 ACTIVE 처리하지 않음
- **결과**: [Phase 2 실행 리포트](./phase2-pipeline-execution-report.md) 참고. 3개 직무 키워드로 원시 후보 30건 수집 → 큐레이션 분리로 21건 추가 → 배제 5건, 검토대기(AMBIGUOUS) 3건, 최종 정규화 약 34건.
- **신규 배제 유형 발견**: `CANDIDATE_SELF_PROMOTION`(구직자 본인의 자기 홍보 게시물), `EDUCATION_PROGRAM_AD`("채용"이라는 단어를 포함하지만 실제로는 교육과정/부트캠프 모집 광고)
- **명시적 마감일 우선 처리 규칙 확정**: 게시물에 마감일이 명시된 경우 실행 시점과 비교해 지났으면 즉시 `EXPIRED`, 마감일 미명시일 때만 `UNKNOWN` 유지

### Phase 3 — 플랫폼 확장 (Threads → Meta/Facebook → X) ✅ 완료
- Phase 1~2에서 검증된 파이프라인을 플랫폼별로 순차 적용
- 플랫폼별 소스 신뢰도 가중치 차등 적용(예: 공식 기업 계정 인증뱃지 유무)
- 플랫폼 간 중복(동일 공고를 여러 SNS에 동시 게시) 제거 로직 추가
- **결과**: [Phase 3 실행 리포트](./phase3-multiplatform-report.md) 참고.
- **핵심 발견**: 직무×플랫폼 조합에 따라 노이즈 비율 편차가 매우 큼 (Threads "UXUI 디자이너 채용"은 노이즈 90%). 채용공고보다 커뮤니티 홍보·연봉 담론·면접 후기·구직 경험담이 압도적으로 많은 조합이 존재.
- **신뢰 큐레이션 계정 식별**: 디자인루키, 윤빌리티, remaincareer, owanimal, 미디어잡 — 이 계정들의 정기 게시물은 상대적으로 신뢰도 높은 소스로 확인. 반대로 순수 커리어 콘텐츠/커뮤니티 계정은 채용 소스로 신뢰하지 않음.
- **신규 배제 유형**: `WRONG_AUDIENCE` (재학생이 아닌 실습 파트너/호스트 기업을 모집하는 공고 등 대상 불일치)
- **교차 플랫폼 중복 규칙**: 동일 큐레이션 계정이 동일 주차 요약을 여러 플랫폼에 동시 게시하는 경우, 대표 소스 1건만 채택

### Phase 4 — Matching 연계 및 운영화
- 정규화된 Job Record를 기존 Matching 입력 포맷에 연결
- 주기적 재수집(신선도 재검증) 스케줄 설계
- 운영 대시보드: 플랫폼별 발견 건수, 신뢰도 분포, 마감 임박 공고 알림

## 5. 파이프라인 상세 (career-job-research 확장)

```
[SNS 검색: Firecrawl] → 후보 게시물 풀
  → 중복 제거 (동일 공고 재게시/플랫폼 간 중복)
  → 신선도 검증 (게시일, 마감일 명시 여부 → ACTIVE/EXPIRING/EXPIRED/UNKNOWN)
  → 출처/계정 검증 (기업 공식 계정 여부, 개인 리그램/지인 공유 여부 구분)
  → 요건 추출 (MUST/PREFERRED/AMBIGUOUS)
  → 정규화 (Job Summary/Source/Deadline/Freshness/Tools/Portfolio/AI/Location/Employment Type)
  → Research Confidence 산출 (SNS 출처는 공식 채용페이지 대비 가중치 하향)
  → Matching 입력으로 전달 (Exclusion Reason 포함)
```

### 5.1 SNS 소스 전용 검증 규칙 (추가 항목, Phase 1 파일럿 반영)
- 게시 계정이 기업 공식 계정인지, 개인 계정의 공유/리포스트인지 구분하여 `Source` 필드에 명시
- 마감일이 게시물에 명시되지 않은 경우 `Freshness = UNKNOWN`으로 표기하고, "게시일로부터 N일 경과" 정보를 함께 기록
- 동일 공고가 여러 플랫폼에 게시된 경우 최초 게시 소스를 대표 Source로, 나머지는 참조 링크로 병합
- 출처 불명확·요건 불명확 공고는 임의로 채우지 않고 `AMBIGUOUS` 또는 `Exclusion Reason`으로 명시 (career-job-research 금지 규칙 준수)
- **배제 유형(Exclusion Reason) 표준 목록** (Phase 1~3 확정): `NOT_A_JOB_POSTING`(채용 트렌드 의견, 커뮤니티/오픈채팅방 홍보, 연봉·커리어 담론, 참고용 기업 리스트, 면접 준비 콘텐츠 등 포함), `CANDIDATE_SELF_PROMOTION`(구직자 본인의 자기 홍보·구직 경험담), `EDUCATION_PROGRAM_AD`("채용" 단어 포함이나 실제로는 교육과정/부트캠프 모집), `WRONG_AUDIENCE`(재학생이 아닌 실습 파트너/호스트 기업 모집 등 대상 불일치), `EXPIRED`(명시된 마감일이 실행 시점 이전)
- **신뢰 큐레이션 계정 화이트리스트**: 디자인루키, 윤빌리티, remaincareer, owanimal, 미디어잡 등 반복 검증된 계정은 소스 신뢰도를 상대적으로 높게 산정. 노이즈 비율이 높은 직무×플랫폼 조합은 일반 키워드 검색 대신 이 계정들을 지정한 검색으로 전환
- **교차 플랫폼 중복 규칙**: 동일 큐레이션 계정이 동일 주차 요약을 여러 플랫폼에 동시 게시한 경우 대표 소스 1건만 채택
- **명시적 마감일 처리**: 게시물에 마감일이 명시되어 있고 실행 시점보다 과거이면 즉시 `EXPIRED`로 배제. 마감일이 명시되지 않은 경우에만 `Freshness = UNKNOWN` 유지
- **소스 신뢰도 등급**: 기업 공식 계정 직접 게시 > 채용 큐레이션 계정 재게시 > 개인 공유/코멘트 순으로 Research Confidence를 차등 적용. 큐레이션 재게시는 기업 공식 채용 페이지로 원문 재확인 전까지 Confidence를 낮게 유지
- **1건 게시물 → N건 Job Record 분리**: 채용 큐레이션 계정이 여러 기업의 공고를 한 게시물에 요약한 경우, 게시물 단위가 아니라 공고 단위로 Job Record를 분리해서 생성
- **1인칭 채용 공지 문구 1차 필터**: "모집합니다/채용합니다/지원 바랍니다" 등 채용 주체가 직접 공지하는 문구가 없는 게시물(채용 트렌드에 대한 개인 의견 등)은 `Exclusion Reason = NOT_A_JOB_POSTING`으로 1차 배제
- **스니펫 한계 명시**: 이 환경의 Firecrawl은 검색 스니펫만 제공(전체 페이지 scrape 불가). 스니펫만으로 채울 수 없는 필드(정확한 마감일, 전체 MUST/PREFERRED 목록)는 임의로 채우지 않고 `UNKNOWN`/`AMBIGUOUS`로 남기며, 원문 링크를 Job Record에 함께 제공

## 6. 리스크 및 고려사항

| 리스크 | 대응 |
|---|---|
| 플랫폼 크롤링 제약(로그인 필요, 동적 렌더링, 봇 차단) | Firecrawl로 접근 가능한 공개 범위만 수집, 접근 불가 시 해당 플랫폼은 수동 리서치로 보완 |
| **(파일럿 확인) Firecrawl이 검색 스니펫만 제공, 전체 페이지 scrape 불가** | 마감일/전체 요건 등 스니펫에 없는 필드는 UNKNOWN/AMBIGUOUS로 유지하고 원문 링크 제공. 고신뢰 후보는 Phase 2에서 수동 원문 확인으로 보완 |
| 채용공고 아닌 콘텐츠(이벤트/공모전 홍보 등) 오탐 | Phase 1 파일럿에서 False Positive율 측정 후 필터 키워드/제외 규칙 보강 |
| 마감일 오표시로 인한 지원 기회 상실 | UNKNOWN 상태 도입, ACTIVE 오표시 금지 원칙 유지 |
| 플랫폼 이용약관 위반 소지 | 공개 페이지·검색 결과 범위 내에서만 수집, 로그인 우회·과도한 요청 금지 |
| SNS 게시물의 낮은 정보 밀도(요건 불명확) | 요건 추출 실패 시 AMBIGUOUS 처리, 필요시 원문 링크만 제공하고 정규화는 보류 |

## 7. 산출물

- 정규화된 SNS 채용공고 Job Record 목록 (career-job-research 출력 포맷 준수)
- 플랫폼별 파일럿 결과 리포트 (Phase 1 종료 시)
- 파이프라인 실행 가이드(스킬+Firecrawl 조합 실행 순서)

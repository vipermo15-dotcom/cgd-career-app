# Phase 3 실행 리포트: Threads → Facebook → X 확장

> 관련 문서: [`sns-job-posting-research-prd.md`](./sns-job-posting-research-prd.md) Phase 3, [Phase 1](./phase1-instagram-pilot-report.md), [Phase 2](./phase2-pipeline-execution-report.md)
> 실행일 기준: 2026-09-13

## 1. 실행 범위

- Threads: "그래픽 디자이너 채용", "UXUI 디자이너 채용" (각 10건, 총 20건)
- Facebook: "그래픽 디자이너 채용" (10건)
- X: "디자이너 채용" (10건) — Phase 1과 동일 쿼리이므로 **동일 결과 재확인만 수행, 신규 분석 없음** (Phase 1 리포트 참고)

## 2. 플랫폼별 노이즈 분석 (핵심 발견)

| 플랫폼 | 쿼리 | 실제 채용공고(직접+큐레이션 재게시) | 노이즈 |
|---|---|---|---|
| Threads | 그래픽 디자이너 채용 | 6/10 | 4/10 |
| **Threads** | **UXUI 디자이너 채용** | **1/10** | **9/10** |
| Facebook | 그래픽 디자이너 채용 | 8/10 | 2/10 |
| X | 디자이너 채용 (Phase 1 재확인) | 4/10 | 6/10 |

**핵심 발견**: Threads의 "UXUI 디자이너 채용" 쿼리는 노이즈 비율이 90%에 달함. 원인은 UX/UI 분야 Threads 생태계가 **채용 공고 자체보다 커뮤니티·정보 공유·커리어 담론 콘텐츠**(단체 카톡방 홍보, 연봉 정보, 면접 후기, 참고용 기업 리스트, 개인 구직 경험담)가 압도적으로 많기 때문. 동일 쿼리라도 직무 키워드에 따라 플랫폼별 신호/노이즈 비율이 크게 달라짐 → **직무×플랫폼 조합별로 노이즈 임계치를 다르게 관리**해야 함.

## 3. 신규 배제 유형 (Phase 3에서 발견)

기존(`NOT_A_JOB_POSTING`, `CANDIDATE_SELF_PROMOTION`, `EDUCATION_PROGRAM_AD`, `EXPIRED`) 외 아래 세부 패턴이 다수 관찰되어, 운영 편의를 위해 `NOT_A_JOB_POSTING`의 하위 유형으로 정리:

- **커뮤니티/오픈채팅방 홍보**: "OO 디자이너 단체 카톡방 모여라" 류 (구인·구직과 무관한 친목/정보공유방 홍보)
- **연봉·커리어 담론**: "OO 직군 평균 연봉", "채용 공고로 보는 필요 역량 분석" 등 채용공고를 소재로 한 2차 콘텐츠 (단, 이런 게시물이 실제 채용공고 목록을 포함하는 경우는 **큐레이션으로 재분류**하여 분리 대상에 포함 — Phase 2 규칙 적용)
- **참고용 기업 리스트**: "OO 직군 채용 경험 있는 회사 100곳 정리" 같은 리서치 자료 (특정 시점의 지원 가능 공고가 아님)
- **면접 준비 콘텐츠**: 면접 질문/답변 정리 게시물
- **대상 불일치(`WRONG_AUDIENCE`, 신규 배제 코드)**: 실습생을 채용할 "파트너/호스트 기업"을 모집하는 공고(예: 인턴십 프로그램의 참여 기업 모집) — 채용 대상이 재학생이 아니라 기업이므로 본 파이프라인의 타깃과 불일치

`CANDIDATE_SELF_PROMOTION`도 해외 구직 경험담(예: "해외에서 UX/UI 롤을 구직하는 4년차 디자이너입니다") 형태로 추가 확인됨 — Phase 2에서 발견한 패턴과 동일 유형.

## 4. 신뢰 가능한 큐레이션 계정(소스) 식별

3개 플랫폼에서 반복적으로 실제 채용 정보를 정확히 정리해 게시하는 계정을 확인:

| 계정 | 플랫폼 | 특징 |
|---|---|---|
| 디자인루키(@designrookie.official) | Instagram | 주간 디자인 채용 큐레이션, 마감일 표기 비교적 정확 |
| 윤빌리티(@yoonbility) | Instagram, Facebook | 주간 채용공고 요약, 다수 대기업/에이전시 포함 |
| remaincareer | Threads | 주 단위 디자이너 채용 정보 업데이트 |
| owanimal | Threads | "채용 공고로 보는 필요 역량" — 요건 분석 + 실제 공고 다수 인용 |
| 미디어잡 | Instagram | 영상/미디어 직군 주간 채용 TOP5 |

→ 이 계정들은 **소스 신뢰도 등급에서 "채용 큐레이션 계정" 중에서도 상위 등급**으로 별도 관리(추후 Matching 입력 시 우선순위 부여 후보)로 제안. 반대로 `uxwoodytips` 등 커리어 콘텐츠/커뮤니티 위주 계정은 채용 큐레이션 소스로 신뢰하지 않음.

## 5. 플랫폼 간 중복 탐지

이번 표본에서는 동일 공고가 서로 다른 플랫폼에 동시 게시된 사례는 발견되지 않음 (표본 크기가 작아 결론 아님 — Phase 4 운영 단계에서 누적 데이터로 재확인 필요). 다만 동일 큐레이션 계정(윤빌리티)이 Instagram과 Facebook에 동일한 주간 요약을 병행 게시하는 패턴은 확인 → **동일 계정의 동일 캡션(주차 표기 일치)은 교차 플랫폼 중복으로 간주하고 대표 소스 하나만 채택**하는 규칙 추가.

## 6. PRD 반영 사항

1. `Exclusion Reason`에 `WRONG_AUDIENCE`(대상이 재학생이 아닌 채용 관련 게시물) 추가
2. 직무×플랫폼 조합별 노이즈 편차가 크므로, Phase 4 운영 시 "노이즈 임계치 초과 조합은 검색 쿼리를 큐레이션 계정 지정 검색(`from:계정명` 형태)으로 전환" 규칙 추가
3. 신뢰 큐레이션 계정 목록을 소스 신뢰도 산정에 반영 (계정 기반 화이트리스트)
4. 동일 큐레이션 계정의 동일 주차 게시물이 여러 플랫폼에 동시 게시된 경우 대표 소스 1건만 채택하는 교차 플랫폼 중복 규칙 추가
